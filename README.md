# TuneAnalyser

コントラバス練習用のリアルタイム・ピッチ＆倍音解析ツール（Webアプリ）。
いまはステップ1「解析エンジンの試作」で、画面は検証用の最小限です。

## できること（ステップ1）

- マイク／USBマイク入力から基本周波数を推定（YIN法、30〜1200Hz、5弦の B0 まで）
- 音名・セント偏差（基準 A4 は変更可。440/442 など）
- 1〜5次倍音の強度（基音比 dB と、1〜5次合計に対する割合）
- 直近1秒のピッチ揺らぎ（標準偏差）
- 遅延の内訳表示と、スピーカー→マイクの往復遅延の実測
- 計測結果を JSON でコピー（結果をそのまま貼って共有できる）
- マイクを使わない「テスト信号」モード（E1 などを内部で合成して解析）

## 実機での確認手順

1. スマホの Chrome で公開URLを開く（マイクは HTTPS か localhost でしか使えません）
2. 「テスト信号で開始」→ E1 で `E1 / +0.0 cent`、倍音の基音比がステータス欄の期待値と一致することを確認
3. 「マイク開始」→ 開放弦 E・A・D・G を弾き、音名とセントが安定するか見る
4. 「往復遅延を測る」→ スピーカー音量を上げて実行
5. 「計測結果をコピー」で JSON を取り、内蔵マイクと H1essential のそれぞれで記録

USBマイク（H1essential）は「マイク」欄で選んでから「マイク開始」を押してください。
ブラウザのエコー除去・ノイズ抑制・自動ゲインはオフにして取り込んでいます（倍音バランスが崩れるため）。

## 遅延の見方

「音→表示の推定」は次の合計です。

- 入力遅延（往復遅延 − 出力遅延。未計測ならブラウザ申告値）
- ブロック長の半分（1024サンプル ≒ 21ms ごとに解析）
- ピッチ解析窓の半分（約33ms。E1 を捉えるため約67msの窓を使う）
- 処理時間（PCで 1〜3ms 程度）
- 画面更新 1 フレーム（約17ms）

倍音の窓は基音の6周期分（E1 で約146ms、G2 で約61ms）なので、倍音表示はピッチ表示より少し遅れます。

## 開発

```sh
npm test        # 合成音での精度テスト（Node 20 以上）
npm run bench   # 音域ごとの誤差と処理時間の一覧
npm run serve   # http://localhost:8080 で起動
```

ビルド不要の ES Modules のみ。依存パッケージなし。

```
src/
  dsp/fft.js        FFT
  dsp/yin.js        ピッチ検出（YIN、差分関数を FFT で計算）
  dsp/harmonics.js  1〜5次倍音の振幅（Goertzel 法で整数倍付近を探索）
  dsp/notes.js      周波数 ⇔ 音名・セント
  engine.js         上をまとめた解析エンジン（DOM 非依存）
  audio/capture-worklet.js  AudioWorklet で 1024 サンプルずつ取り出す
  audio/loopback.js 往復遅延計測（チャープの相互相関）
  main.js           検証用UI
```
